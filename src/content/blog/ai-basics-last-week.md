## 음성: 소리가 어디로 가는지부터

회의를 받아쓰고 회의록으로 정리하는 도구를 만들었습니다. 엔진을 두 개 갈아 끼울 수 있게 했습니다.

| 엔진 | 도는 곳 | 실시간 | 소리가 밖으로 |
| --- | --- | --- | --- |
| faster-whisper | 내 PC (CPU) | 안 됨 | 안 나감 |
| nemotron 0.6B | 원격 GPU 서버 | 됨 | 나감 |

기본값은 내 PC에서 도는 쪽으로 뒀습니다. 회사 회의 녹음에는 개인정보와 영업 비밀이 들어 있기 때문입니다.
빠르고 실시간으로 되는 쪽이 있어도, 어떤 소리를 넣을지에 따라 못 쓰는 경우가 있었습니다.

## 3D: AI가 하는 일은 가운데 한 칸

폰 영상 하나에서 3차원 장면을 만들어 웹에 올리는 실습이었습니다. [결과 보기](https://rome777.github.io/room-3d/my-open-space/)

![브라우저에서 돌려 볼 수 있는 3D 정원 장면](/blog/images/posts/sept-room3d.jpg)

<small>직접 찍은 영상이 아니라 공개 데이터셋의 정원 장면으로 돌린 연습 실행입니다.</small>

```mermaid
flowchart LR
    V["영상"] --> P["사진 24장"]
    P --> D["점"]
    D --> S["알갱이"]
    S --> C["줄인 파일"]
    C --> W["웹 주소"]

    classDef ai fill:#fef3c7,stroke:#b45309,stroke-width:3px,color:#111827
    classDef file fill:#e5e7eb,stroke:#4b5563,color:#111827
    class D ai
    class V,P,S,C,W file
    linkStyle 0,2,3,4 stroke:#6b7280,stroke-width:2px
    linkStyle 1 stroke:#b45309,stroke-width:3px
```

<small>사진에서 점을 만드는 한 칸만 AI가 합니다. 나머지는 파일을 바꾸는 일입니다.</small>

시간은 AI가 아닌 칸에서 다 썼습니다. 에러 없이 조용히 실패하는 자리가 많았습니다.

| 증상 | 원인 |
| --- | --- |
| 사진 8장까지는 되고 본 실행에서 메모리가 넘침 | 기본 설정이 무료 Colab GPU에 없는 연산 방식 |
| 파일이 3.6배로 커짐 | 쓰지 않는 칸 45개를 헤더에 넣음 |
| 오류 없이 화면만 까맘 | 렌더러를 장면에 넣지 않음 |
| 압축 파일이 안 열림 | 만드는 도구는 4판으로 쓰는데 뷰어는 3판까지만 읽음 |

Colab을 제 PC의 코딩 도구에 붙이는 것도 그냥은 안 됐습니다. 연결은 되는데 도구가 하나밖에 안 보였습니다.
도구 목록 요청이 연결보다 먼저 도착해서 빈 목록을 받아 가는 순서 문제였고, 사이에 중계기를 하나 끼워서 풀었습니다.

## AI가 새로 들어간 분야

표, 유전체, 세포 영상, 단백질, 분자, 기상, 수학 증명, 로봇. 여덟 분야를 하루에 훑었습니다.
분야는 여덟 개인데 밑에 깔린 방법은 네 개였습니다.

![여덟 분야가 돌려 쓰는 네 가지 방법](/blog/images/posts/sept-eight-fields.png)

그중 시계열 기반 모델을 직접 돌렸습니다. 학습 없이 표만 넣어도 예측이 나옵니다.

| 모델 | 크기 | 오차 (작을수록 좋음) |
| --- | --- | --- |
| 지난해 같은 달 값 그대로 쓰기 | | 47.8 |
| chronos-bolt-tiny | 870만 | 27.1 |
| chronos-bolt-small | 4,770만 | 18.9 |
| chronos-bolt-base | 2억 530만 | 22.3 |
| chronos-2 | 1억 1,950만 | 13.4 |

가장 작은 모델도 "지난해 같은 달 값"이라는 기준선을 이겼습니다. 그런데 네 배 큰 base가 small보다 나빴습니다. 자료가 132개월치뿐이라 짧았기 때문입니다.
큰 모델이 정답이 아니라는 것, 그리고 비교할 기준선이 있어야 "좋다"는 말을 할 수 있다는 것을 이 표에서 배웠습니다.

## Main Quest: 파인튜닝 모델로 API를 대체할 수 있나

제가 따로 운영하는 파이프라인이 커뮤니티 글의 감성분류를 Gemini API에 맡기고 있습니다. 그 자리에 제 PC에서 도는 한국어 파인튜닝 모델을 넣을 수 있는지 쟀습니다.
성공 기준은 모델을 돌리기 전에 적어 뒀습니다. 일치율 70% 이상, 긍정과 부정을 뒤집는 오류 2건 이하입니다.

| 후보 | 일치율 | 방향 반전 | 건당 시간 |
| --- | --- | --- | --- |
| Gemini 2.5 Flash API (지금 방식) | 65% | 0건 | 6.25초 |
| KcELECTRA 파인튜닝 | 60% | 3건 | 0.08초 |
| KR-FinBert-SC 파인튜닝 | 55% | 3건 | 0.08초 |
| KoELECTRA 파인튜닝 | 45% | 6건 | 0.08초 |
| klue/roberta 파인튜닝 | 40% | 6건 | 0.08초 |
| 키워드 규칙 | 35% | 0건 | 0초 |

파인튜닝 후보 네 개가 모두 기준을 못 넘어서 채택하지 않았습니다. "지금 방식이 낫다"도 실험 결과입니다.

다만 이 표의 숫자는 정확도가 아닙니다. 정답 라벨을 사람이 아니라 Claude가 매겼고, 그것도 Gemini의 답을 본 상태에서 매겼습니다. 검증 세트도 20건뿐입니다.
그래서 보고서에는 결론보다 이 한계를 먼저 적었습니다. "파인튜닝이 안 된다"고 말하려면 검증 세트부터 사람이 다시 만들어야 합니다.

방향을 뒤집은 3건은 모두 비속어가 낀 문장이었습니다. 학습 데이터가 Gemini 라벨을 그대로 베낀 2,676건이라, 모델이 거친 말이 누구를 향하는지까지는 배우지 못한 것으로 보입니다.

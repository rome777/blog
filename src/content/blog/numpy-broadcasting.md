`(3, 1)` 배열과 `(1, 4)` 배열을 더했더니 `(3, 4)`가 나왔습니다.
에러가 나야 할 것 같은데 왜 되는지 정리했습니다.

## 규칙은 두 줄이 전부

두 배열의 shape를 **오른쪽 끝부터** 하나씩 맞춰봅니다.

1. 두 값이 같으면 통과
2. 둘 중 하나가 `1`이면 그 축을 늘려서 맞춤

둘 다 아니면 에러입니다.

```python
import numpy as np

a = np.array([[1], [2], [3]])   # (3, 1)
b = np.array([[10, 20, 30, 40]]) # (1, 4)

print((a + b).shape)  # (3, 4)
```

맞춰보는 과정은 이렇습니다.

```text
a:  (3, 1)
b:  (1, 4)
     ↓  ↓
     3  4   ← 각 축에서 1이 아닌 쪽을 따라감
```

## 왜 메모리를 안 먹는가

늘린다고 실제로 복사하지는 않습니다. stride를 0으로 두고 같은 값을 계속 읽을 뿐입니다.
그래서 `(10000, 1)`과 `(1, 10000)`을 더해도 중간 배열이 만들어지지 않습니다.

## 조용히 틀리는 경우

브로드캐스팅이 편한 만큼, **의도하지 않았는데 연산이 성공해버리는** 게 진짜 함정입니다.

```python
pred  = np.array([1.0, 2.0, 3.0])       # (3,)
label = np.array([[1.0], [2.0], [3.0]]) # (3, 1)

error = pred - label
print(error.shape)  # (3, 3) — 원했던 건 (3,) 였는데!
```

`(3,)`와 `(3, 1)`이 만나면 `(3, 3)`이 됩니다. 에러가 없으니 손실값이 이상해질 때까지 눈치채기 어렵습니다.

| 왼쪽 | 오른쪽 | 결과 | 의도한 것? |
| --- | --- | --- | --- |
| `(3,)` | `(3,)` | `(3,)` | ⭕ |
| `(3,)` | `(3, 1)` | `(3, 3)` | ❌ |
| `(3, 1)` | `(1, 3)` | `(3, 3)` | 보통 의도한 것 |

## 습관으로 만든 것

레이블을 만들 때 `reshape(-1)` 로 축을 눌러두고, 손실 계산 직전에 shape를 한 번 찍어봅니다.

```python
assert pred.shape == label.shape, f"{pred.shape} != {label.shape}"
```

이 한 줄로 디버깅 시간을 꽤 아꼈습니다.
